# learning-app

[![GitHub Pages](https://img.shields.io/static/v1?label=GitHub+Pages&message=+&color=brightgreen&logo=github)](https://kanpurin.github.io/learning-app/)

FSRS (Free Spaced Repetition Scheduler) を使った、ブラウザ上で動く学習用クイズアプリです。問題を作成・編集し、JSONやFirebaseに保存しながら、タグや復習タイミングに応じて出題できます。

## 期限付き学習

誤答後は最低10分待ち、ほかの問題を5回答挟んでから再出題します。出せるほかの問題がない場合は回答数の条件だけを緩め、10分とFSRSの復習時刻の両方を過ぎてから再開します。FSRSがより長い間隔を指定した場合は短縮しません。無限モードでも誤答直後の再出題を抑止します。5回答の条件と無限モードの待ち時間は画面を開いている学習セッション内で管理し、通常モードの最低10分はカードのdueに保存します。待機中は「復習待ち」と表示し、画面を開いたままなら再開時刻を約10秒ごとに確認します。10分・5回答は実用上の設定であり、研究で保証された最適値ではありません。

「期限付き」では、対象の全問題を目標日までに習得することを回答数の目安より優先します。目標日、1日の回答数の目安、各問題の目標記憶率（80%、90%、95%）を設定します。選択タグに一致する問題が対象です。目標日は端末のローカル日付の当日末まで有効です。

問題画面の主表示は「今日の目標・1日の学習目安・完了・あと何回答」です。全未達数を今日の残りとして表示しません。未学習数や期限までの試算は、折りたたみの「期限までの全体進捗」にまとめています。未達数を残り日数で割っただけの値を「1日あたりの目安」としては表示しません。試算できない場合も暫定の回答目安を数値で表示し、期限に間に合うかは未確認と明記します。

今日の目標は、設定した回答数の目安と「今日の回答済み数＋今後必要と試算した回答数」を残り日数で割って切り上げた数の、大きい方です。各問題で1回誤答する試算を優先し、それが計算できない場合は全てGoodの試算、両方計算できなければ必要回答数の下限を使い暫定と表示します。学習開始時の目標を日別集計に保存し、回答のたびに増減しません。目標日・目標記憶率・設定した回答目安を変更した場合と日付が変わった場合は再計算します。

今日の目標に達したら、回答の解説・評価を確認して次へ進んだ時点で「今日の目標を達成しました」と表示します。全体目標の達成とは区別し、自動再出題を止めます。「追加学習する」で期限優先の出題を続けられます。今日の目標は上限ではなく、学習の区切りです。全体目標が先に推定上達成された場合は、残りの今日の回答を要求しません。

新規導入の目安も保存し、未学習数を残り日数から1日を引いた日数（最低1日）で割って切り上げます。導入目安に達して通常復習が可能な場合は通常復習を優先し、復習と新規導入を配分します。ほかに出せる問題がないときは新規導入を追加できるため、この目安は厳密な上限ではありません。

- 設定した回答数の目安は強制的な上限ではありません。今日の目標に達したら区切りを表示し、追加学習を選ぶと継続できます。全ての未学習問題を期限までの導入対象にし、新規問題の導入を期間の80%へ日割りする旧方式は使いません。
- 出題順は、出題可能になった学習・再学習、未学習、目標記憶率に届かない通常復習の順です。学習・再学習と未学習が両方ある場合は、当日の回答数の偶奇で交互に選び、再学習が多くても新規導入が止まらないようにします。通常復習は目標日の予測記憶率が低い問題を優先します。回答時間は使いません。
- 通常復習のdueが目標日より先でも、目標日に記憶率が不足する問題は対象に残します。同じ問題を即座に繰り返さないよう、最後の評価から最低10分空けます。学習・再学習は、10分とFSRSのdueの両方を過ぎてから出題します。
- 各問題は「学習済み（reps > 0）」「通常復習状態（state = Review）」「今後復習しない場合でも目標日の予測記憶率が設定以上」の全条件で推定上の目標到達とします。全問が条件を満たすまで未達数が残り、平均記憶率が高いだけでは到達扱いにしません。
- 未達が残っていて出題可能な問題がなければ「復習待ち」、全問が条件を満たせば「全問が目標記憶率以上です（推定）」と表示します。対象0問は目標達成扱いにしません。期限を過ぎた場合は期限超過と残り未達数を表示し、回答を停止します。「今回の学習を終えました」という曖昧な完了表示は期限付きでは使いません。
- 必要回答数の下限は未達問題数、1日あたりの下限はそれを残り日数（残り時間を24時間単位で切り上げ、最低1日）で割って切り上げた数です。これは各問題に最低1回ずつ回答する分だけで、誤答や追加復習による回答は含みません。目安を超える場合は追加学習が必要と表示します。
- 追加復習込みの回答数も試算します。現在の各カードをコピーし、「今後すべてGood（普通）で正答」「未達の各問題で最初に1回Again（誤答）、その後Goodで正答」の2ケースをFSRSで進め、全カードが目標条件を満たすまでの回答数を合計します。同じ問題の反復も1回ずつ数え、残り日数で割った1日平均を表示します。各回答後に再計算します。
- 試算は10分の待機と学習・再学習のdueを考慮します。通常復習はFSRSのdueと最後の復習の翌日のうち早い方（最低10分後）まで進め、日を空けた復習の効果を計算します。10分おきの反復だけで到達を計算する旧試算は使用しません。試算の変更時は保存済みの日別目標を一度更新し、その後は回答中に目標を動かしません。
- 問題ごとに独立に試算するため、別問題を5回答挟む条件や、1日に実際に確保できる学習枠、回答所要時間は含みません。通常復習をすぐ再出題できる実際の出題順と、この翌日復習の試算は同一ではありません。100回答以内で到達しないカード、期限を越えるカード、不正な履歴がある場合は総数を断定せず、試算できない問題数を表示します。2ケースは予測区間や成功確率ではなく仮定を置いた試算であり、必要回答数の上限・最小値・達成保証を示すものではありません。
- 10分待機やFSRSの再学習時刻が期限より後になる問題は、期限前に再学習できない旨を表示します。期限直前に無条件で反復して達成扱いにはしません。
- 表示する平均記憶率は「今後復習しない場合の目標日の予測記憶率」で、未学習カードを0として計算します。今後の計画を全て実行した場合の成績予測ではありません。

期限付きの従来の最大2回先読み・回答枠内での効率優先の割り当ては使いません。未達問題を残さないことを優先して、実際の回答・評価から繰り返し判定します。FSRSは記憶モデルであり、推定上の到達も期限当日の全問正答を保証しません。必要回答数の下限だけで期限内の実現可能性を保証するものでもありません。

設定と日別の回答数はlocalStorageに保存します。回答数は同じ問題セット（問題文・タグ・配列順）と選択タグの組み合わせごとに集計し、初回評価で新規数を1増やし、再学習を含む各評価で回答数を1増やします。日付が変わると当日の集計が切り替わります。以前のdailyLimit設定はそのまま回答数の目安として引き継ぎます。別端末との同期、JSONへの計画の出力には対応していません。ブラウザの保存機能が利用できない場合は画面を閉じると設定・当日の集計が失われます。

## 主な機能

- 複数形式のクイズに対応
  - 単一選択問題
  - 複数選択問題
  - 並べ替え問題
  - 単語入力問題
- FSRSによる復習スケジューリング
  - 期限を迎えた学習・再学習、通常の復習、新規問題の順に出題
  - 新規問題の上限を学習開始時に設定（初期値は1回につき10問）
  - 回答後に「もう一回」「難しい」「普通」「簡単」で記憶状態を更新
  - 短期記憶モード、長期記憶モード、無限出題モードを選択可能
  - 期限付きモード：目標日、目標記憶率、1日の回答目安を設定し、未達問題が残る間は上限で停止しない
- タグによる出題範囲の絞り込み
  - 問題にタグを付与
  - クイズ開始時にタグを選んで対象問題をフィルタ
- 問題の作成・編集・削除
  - アプリ上で新しい問題を作成
  - 既存問題の本文、選択肢、正答、解説、タグを編集
  - 問題の削除フラグ管理
  - 未保存の編集がある状態でクイズへ戻ることを防止
- JSONファイルの読み込み・書き出し
  - 問題データと学習履歴をJSONとしてインポート
  - 現在の問題データをJSONとしてダウンロード
  - 削除済み問題はエクスポート対象から除外
- Firebase連携
  - Googleログイン
  - Firestore上の問題セット一覧を読み込み
  - 問題セットの新規保存
  - 既存問題セットへの上書き保存
- ブラウザ内のローカル保存
  - IndexedDB (Dexie) に問題、ファイル名、選択中タブを保存
  - ページを再読み込みしても作業状態を復元
- Markdown表示
  - 問題文、選択肢、解説をMarkdownで表示
  - GitHub Flavored Markdown、改行、数式表示(KaTeX)に対応
- 選択肢のランダム表示
  - 問題ごとに選択肢のシャッフルを設定可能

## 画面構成

- クイズ: 記憶モードとタグを選んで問題を解きます。
- 作成: 問題形式を選び、新しい問題を追加します。
- 編集: 登録済み問題を一覧から開いて編集・削除します。
- サイドバー: JSONの読み込み・保存、Googleログイン、Firebaseの読み書きを行います。

## 問題データ

問題データは、問題オブジェクトを並べたJSON配列です。JSONファイルを読み込む場合は、ファイル全体が次のような配列になっている必要があります。

```json
[
  {
    "summary": "HTTPステータスコードの基本",
    "problem": "成功を表すHTTPステータスコードはどれですか？",
    "options": ["200", "301", "404", "500"],
    "answer": [1],
    "explanation": "200 OK はリクエストが成功したことを表します。",
    "type": "mcq",
    "tags": ["web", "http"],
    "card": {
      "due": "2026-05-25T13:16:21.353Z",
      "stability": 0,
      "difficulty": 0,
      "elapsed_days": 0,
      "scheduled_days": 0,
      "reps": 0,
      "lapses": 0,
      "state": 0
    },
    "random": false
  }
]
```

### 全体フォーマット

- ルート要素は配列です。
- 配列の各要素が1問分の問題オブジェクトです。
- JSONとして正しい形式である必要があります。コメント、末尾カンマ、シングルクォートは使えません。
- アプリからエクスポートしたJSONには、問題本文だけでなくFSRSの学習履歴も含まれます。
- 手書きで新規作成する場合、`card` は省略できます。読み込み時に未学習状態のカードが自動作成されます。

### フィールド一覧

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `summary` | string | 任意 | 編集画面の一覧に表示する問題の短いタイトルです。省略時は空文字になります。 |
| `problem` | string | 推奨 | 問題文です。Markdown、KaTeX数式を利用できます。 |
| `options` | string[] または null | 問題形式による | 選択肢です。`mcq`、`mrq`、`order` では2件以上を推奨します。`word` では `null` または空配列で構いません。 |
| `answer` | number[] または string | 必須 | 正答です。問題形式によって型と意味が変わります。詳しくは「問題形式ごとの書き方」を参照してください。 |
| `explanation` | string | 任意 | 回答後に表示する解説です。Markdown、KaTeX数式を利用できます。 |
| `type` | string | 任意 | 問題形式です。`mcq`、`mrq`、`order`、`word` のいずれかを指定します。省略時は `mcq` として扱われます。 |
| `tags` | string[] | 任意 | 出題時の絞り込みに使うタグです。省略時は空配列になります。 |
| `card` | object | 任意 | FSRSの学習履歴です。省略時は未学習状態のカードが自動作成されます。 |
| `random` | boolean | 任意 | `true` にすると出題時に選択肢の表示順をシャッフルします。省略時は `false` です。 |

### 問題形式ごとの書き方

#### 単一選択問題: `mcq`

1つだけ正解がある選択問題です。

- `type`: `"mcq"`
- `options`: 選択肢の配列
- `answer`: 正解の選択肢番号を1つだけ入れた配列
- 選択肢番号は0始まりではなく、1始まりです。

```json
{
  "summary": "HTTP 200",
  "problem": "成功を表すHTTPステータスコードはどれですか？",
  "options": ["200", "301", "404", "500"],
  "answer": [1],
  "explanation": "`200 OK` は成功レスポンスです。",
  "type": "mcq",
  "tags": ["web", "http"],
  "random": true
}
```

この例では、`options[0]` の `"200"` が正解なので `answer` は `[1]` です。

#### 複数選択問題: `mrq`

複数の正解がある選択問題です。

- `type`: `"mrq"`
- `options`: 選択肢の配列
- `answer`: 正解の選択肢番号をすべて入れた配列
- 回答時は、選んだ番号の集合が `answer` と完全一致した場合に正解になります。

```json
{
  "summary": "JavaScriptのプリミティブ",
  "problem": "JavaScriptのプリミティブ型をすべて選んでください。",
  "options": ["string", "number", "Array", "boolean"],
  "answer": [1, 2, 4],
  "explanation": "`Array` はオブジェクトです。",
  "type": "mrq",
  "tags": ["javascript"],
  "random": false
}
```

この例では、`string`、`number`、`boolean` が正解です。

#### 並べ替え問題: `order`

選択肢を正しい順番に並べる問題です。

- `type`: `"order"`
- `options`: 並べ替え対象の配列
- `answer`: 正しい順序で選択肢番号を並べた配列
- 選択肢番号は1始まりです。

```json
{
  "summary": "HTTPリクエストの流れ",
  "problem": "一般的なHTTP通信の流れを正しい順番に並べてください。",
  "options": ["レスポンスを受け取る", "リクエストを送る", "画面に反映する"],
  "answer": [2, 1, 3],
  "explanation": "まずリクエストを送り、レスポンスを受け取り、最後に画面へ反映します。",
  "type": "order",
  "tags": ["web", "http"],
  "random": false
}
```

この例では、表示上の選択肢2、1、3の順に選ぶと正解です。

#### 単語入力問題: `word`

テキスト入力で答える問題です。

- `type`: `"word"`
- `options`: `null` または空配列
- `answer`: 正解文字列
- 入力値と `answer` が完全一致した場合に正解になります。大文字小文字、空白、全角半角の違いも区別されます。

```json
{
  "summary": "Reactの状態管理",
  "problem": "Reactでコンポーネント内の状態を扱う基本的なHook名は？",
  "options": null,
  "answer": "useState",
  "explanation": "`useState` は関数コンポーネントで状態を扱うためのHookです。",
  "type": "word",
  "tags": ["react"],
  "random": false
}
```

### Markdownと数式

`problem`、`options`、`explanation` はMarkdownとして表示されます。

利用できる主な記法:

- 見出し、箇条書き、太字、インラインコード、コードブロック
- GitHub Flavored Markdownの表
- KaTeXによる数式

安全のため、JSONやFirebaseから読み込んだHTMLタグはHTMLとして解釈しません。画像を入れたい場合はMarkdownの画像記法を使います。

例:

```json
{
  "summary": "二次方程式",
  "problem": "次の式の解を考えます。\n\n$$x^2 - 4 = 0$$",
  "options": ["$x = 2$", "$x = -2$", "$x = \\pm 2$"],
  "answer": [3],
  "explanation": "$$x^2 = 4$$ より、解は $x = \\pm 2$ です。",
  "type": "mcq",
  "tags": ["math"],
  "random": false
}
```

JSON文字列内で改行を書く場合は `\n` を使います。バックスラッシュを含む数式を書く場合は、JSONのエスケープ規則に従って `\\` のように書く必要があります。

### FSRSの `card`

`due` と `last_review` は保存時にISO 8601文字列へ統一します。読み込み時はISO文字列、Date、FirebaseのTimestamp（`toDate()`または`seconds`・`nanoseconds`）をDateへ変換します。古いFirebaseデータの日時も変換し、学習回数・難易度・安定度などの履歴は保持します。

`card` は復習スケジューリング用の学習履歴です。手作業で問題を作るだけなら省略して構いません。省略時は次のような未学習状態が自動で補われます。

```json
{
  "due": "2026-05-25T13:16:21.353Z",
  "stability": 0,
  "difficulty": 0,
  "elapsed_days": 0,
  "scheduled_days": 0,
  "reps": 0,
  "lapses": 0,
  "state": 0
}
```

各項目の意味:

| フィールド | 説明 |
| --- | --- |
| `due` | 次回復習予定日時です。ISO 8601形式の日時文字列として保存されます。 |
| `stability` | 記憶の安定度です。FSRSが更新します。 |
| `difficulty` | 問題の難しさです。FSRSが更新します。 |
| `elapsed_days` | 前回レビューからの経過日数です。 |
| `scheduled_days` | 次回レビューまでの日数です。 |
| `reps` | レビュー回数です。0なら未学習として扱われます。 |
| `lapses` | 忘却、または失敗した回数です。 |
| `state` | FSRS内部のカード状態です。 |
| `last_review` | レビュー後に追加されることがある最終レビュー日時です。 |

アプリは、`reps` が `1` 以上で `due` が現在時刻以前の問題を復習対象とします。その中で `state` が学習・再学習の問題を優先し、次に通常の復習、最後に `reps` が `0` の新規問題を出題します。同じ優先度内ではランダムです。将来の復習予定は前倒ししません。

新規問題は1回の学習につき初期値10問までで、開始画面で0〜1000問に変更できます。初めて回答して評価した時点で1問として数え、その問題の再学習は上限に含めません。上限は日単位ではなく、クイズ画面を開き直すとリセットされます。残り問題数は期限を迎えた問題数と、上限内の新規問題数の合計です。無限モードはこの上限と復習期限を使いません。

### 読み込み時の補完ルール

JSON読み込み時、足りない項目は次のように補われます。

| 項目 | 補完値 |
| --- | --- |
| `problem` | `""` |
| `options` | `[]` |
| `answer` | `""` |
| `explanation` | `""` |
| `type` | `"mcq"` |
| `summary` | `""` |
| `deleted` | `false` |
| `tags` | `[]` |
| `card` | 未学習状態のFSRSカード |
| `random` | `false` |

ただし、補完されるからといって全ての問題が有効になるわけではありません。実際に解ける問題にするには、問題形式に合った `options` と `answer` を指定してください。

### 書き出し時のルール

アプリからJSONを書き出すと、各問題は次の項目だけを含みます。

- `problem`
- `options`
- `answer`
- `explanation`
- `type`
- `summary`
- `tags`
- `card`
- `random`

編集画面で削除した問題は内部的には `deleted: true` になりますが、JSON書き出し時には除外されます。そのため、エクスポートしたJSONには `deleted` は含まれません。

### Firebase保存時の形式

Firestoreには `questionSets` コレクションへ、次の形式のドキュメントとして保存します。

```json
{
  "name": "問題セット名",
  "questions": [
    {
      "summary": "HTTPステータスコードの基本",
      "problem": "成功を表すHTTPステータスコードはどれですか？",
      "options": ["200", "301", "404", "500"],
      "answer": [1],
      "explanation": "200 OK はリクエストが成功したことを表します。",
      "type": "mcq",
      "tags": ["web", "http"],
      "card": {
        "due": "2026-05-25T13:16:21.353Z",
        "stability": 0,
        "difficulty": 0,
        "elapsed_days": 0,
        "scheduled_days": 0,
        "reps": 0,
        "lapses": 0,
        "state": 0
      },
      "random": false
    }
  ],
  "updatedAt": "Firestore server timestamp"
}
```

JSONファイルとして読み書きする場合は、Firestore用の外側の `name`、`questions`、`updatedAt` は不要です。JSONファイルでは `questions` の中身、つまり問題オブジェクトの配列だけを書きます。
